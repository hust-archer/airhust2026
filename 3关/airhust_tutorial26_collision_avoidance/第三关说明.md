# 第三关 人工势场法避障 —— 实现与调试报告

---

## 一、任务与场景

### 1.1 场景

`collision_1.world` 中放置两根圆柱作为障碍物：

- 柱子一：`pose = (3.048, -0.522, 1.0)`，半径 0.5 m，高 2 m
- 柱子二：`pose = (3.048, +0.522, 1.0)`，半径 0.5 m，高 2 m

两柱中心相距 1.044 m，减去各自半径后，**边缘之间的缝隙只有 4.4 cm**。飞机半径远大于这个值，无法从中间穿过，必须横向绕行一个柱径以上。

任务二使用的 `collision_2.world` 里只有一根柱子，位置是 `(3.048, 0.022)`，半径 0.5、高 2。它几乎正好压在起点到目标的连线上，横向只偏了 2.2 厘米。

### 1.2 目标

从原点 `(0, 0)` 起飞，依靠激光雷达点云实时感知，绕过障碍飞到 `(6, 0)`。

## 二、算法设计

### 2.1 总体结构

控制量由两部分速度相加而成：

```text
v_sp = v_track + R(yaw) · v_collision
```

- `v_track`：指向目标的跟踪速度，在**世界系**下直接计算
- `v_collision`：远离障碍的排斥速度，在**机体系**下计算
- `R(yaw)`：把机体系速度旋转到世界系的旋转矩阵

### 2.2 引力项（跟踪速度）

```cpp
vel_track[0] = p_xy * (target_x - local_pos.pose.pose.position.x);
vel_track[1] = p_xy * (target_y - local_pos.pose.pose.position.y);
```

本质是一个比例控制器：误差越大速度越大。`p_xy = 0.7` 是比例增益。

限幅方式与后面的避障速度保持一致，用**最大分量**而不是向量模长：

```cpp
float vel_max = (fabs(vel_track[0]) >= fabs(vel_track[1]))
              ? fabs(vel_track[0]) : fabs(vel_track[1]);
if (vel_max > vel_track_max)
{
    for (int i = 0; i < 2; i++)
        vel_track[i] = vel_track[i] * vel_track_max / vel_max;
}
```

选择最大分量是因为上限 `vel_track_max = 0.3` 约束的是「某一个轴的速度」，不是斜向合成的速度。这样限幅后单轴速度一定不超限。

### 2.3 斥力项

先求最近障碍物的距离 `distance_c` 和方位 `angle_c`，再转成机体系下的两个分量：

```cpp
distance_cx = distance_c * cos(angle_c / 180 * 3.1415926);
distance_cy = distance_c * sin(angle_c / 180 * 3.1415926);
```

注意 `angle_c` 的单位是**度**，所以必须除以 180 再乘 π，不能直接把 `angle_c` 传给 `cos()`。

斥力大小分三段：

```cpp
if (distance_c < R_inside)
{
    // 内圈：斜率 p_r，强力顶开
    F_c = p_R * (R_outside - R_inside)
        + p_r * (R_inside - distance_c);
}
else
{
    // 外圈：斜率 p_R，温和推
    F_c = p_R * (R_outside - distance_c);
}
```

三段结构如下：

- `ρ > R_outside`：`F_c = 0`，不避障
- `R_inside < ρ ≤ R_outside`：`F_c = p_R (R_outside - ρ)`，随着靠近线性增大
- `ρ ≤ R_inside`：`F_c = p_R (R_outside - R_inside) + p_r (R_inside - ρ)`，斜率换成更大的 `p_r`

连续性验证：

- 在 `ρ = R_outside` 处，第一段给 0，第二段也给 `p_R × 0 = 0`，连续
- 在 `ρ = R_inside` 处，第二段给 `p_R (R_outside - R_inside)`，第三段的第一项恰好也是它，连续

所以整条曲线是分段线性但不跳变的。

```cpp
vel_collision[0] -= F_c * distance_cx / distance_c;
```

`distance_cx / distance_c` 是从飞机指向障碍的单位向量，取负号变成反向，所以 `F_c` 乘以单位向量得到的就是速度。`p_R`、`p_r` 是这条直线的**斜率**，不是增益系数。

### 2.4 坐标系变换

```cpp
void rotation_yaw(float yaw_angle, float input[2], float output[2])
{
    float c = cos(yaw_angle);
    float s = sin(yaw_angle);
    output[0] = input[0] * c - input[1] * s;
    output[1] = input[0] * s + input[1] * c;
}
```

就是一个标准的二维旋转矩阵 `R(+yaw)`：

```text
[ cos  -sin ]
[ sin   cos ]
```

机体系到世界系用 `+yaw`。速度是自由矢量，**只需要旋转，不需要平移**——这一点和坐标点变换不同，坐标点变换才要加上原点偏移。

### 2.5 对称场景下的迟滞处理

问题：两根柱子关于 `y = 0` 完全对称，起点和目标也都在 `y = 0` 上。理论上两根柱子产生的横向推力大小相等、方向相反，净横向分量严格为零。

实际不为零，但只剩千分之几 m/s 的残差，来自点云 `voxel_leaf_size = 0.2` 的栅格量化误差。这个残差每帧都在零附近翻号，导致 `angle_c` 来回跳变，横向推力互相抵消，飞机在柱子前震荡不前，而跟踪速度还在推它向前，最终撞柱。

解决方法：引入状态记忆，第一帧进入避障时把方向锁死。

```cpp
static int avoid_side = 0;   // 函数内静态变量，跨帧保留

if (avoid_side == 0)
{
    avoid_side = (ry >= 0.0f) ? 1 : -1;
}

if (fabs(ry) < 0.4f * F_c)
{
    ry = avoid_side * 0.4f * F_c;
}
```

第二段的作用是：如果算出来的横向分量太小（小于斥力的 40%），就用锁定的方向强行撑到这个下限。这保证了即使扰动再次让 `ry` 翻号，输出也始终偏向同一侧。

`avoid_side` 在退出避障区域时归零，这样下一个障碍物可以重新选择方向。

## 三、关键代码

### 3.1 避障主流程

```cpp
// 判断是否进入避障
if (distance_c >= R_outside)
    flag_collision_avoidance.data = false;
else
    flag_collision_avoidance.data = true;

// 跟踪速度
vel_track[0] = p_xy * (target_x - pos.x);
vel_track[1] = p_xy * (target_y - pos.y);
// ... 限幅

vel_collision[0] = 0;
vel_collision[1] = 0;

// 避障速度
if (flag_collision_avoidance.data == true)
{
    // ... 计算 F_c、rx、ry
}

// 转到世界系后合成
rotation_yaw(yaw, vel_collision, vel_collision_ENU);
vel_sp_ENU[0] = vel_track[0] + vel_collision_ENU[0];
vel_sp_ENU[1] = vel_track[1] + vel_collision_ENU[1];
```

### 3.2 三层限幅

整个链路里有三处限幅，各管各的，不能合并：

- `vel_track` 限到 `vel_track_max = 0.30`：约束跟踪速度
- `vel_collision` 限到 `vel_collision_max = 0.30`：约束避障分量
- `vel_sp_ENU` 限到 `vel_sp_max = 0.30`：约束合成后的总速度

第三层是必须的，因为前两层各自不超限不代表加起来不超限。两个 0.3 相加就是 0.6，会超出飞机实际允许的速度。

限幅时必须**全体乘以同一个正数**，否则方向会变：

```cpp
float k = vel_collision_max / vc_max;
vel_collision[0] *= k;
vel_collision[1] *= k;
```

## 四、调试过程记录

### 4.1 `z_band` 过窄导致障碍物被整根滤掉

做任务二（`collision_2.world`）时出现了一个非常反常的现象：飞机对正前方的柱子完全不理会，直着撞上去。

查日志发现 `vel_collision_x` 和 `vel_collision_y` 每一帧都是 0，也就是避障分支从未进入过。这说明 `distance_c` 一直大于 `R_outside = 1.6`，感知端根本没有看到柱子。

问题出在 `cloud_cb()` 的这个门限：

```cpp
if (fabs(z - pz) > z_band) continue;
```

`z_band` 默认是 `0.10`，只保留与飞机高度相差 10 厘米以内的点。而 Livox 是固态激光雷达，扫描线之间存在间隔，打在柱子上是一圈一圈稀疏的环带而不是连续的面。只要飞机的实际高度和某一圈扫描线错开十几厘米，整根柱子上就一个点都进不了切片，`bin_range` 全部保持 `NO_OBSTACLE`。

修复方法是放宽 `z_band`。先试到 `0.50`，避障立刻恢复正常；随后进一步收窄到 `0.30` 复测，同样稳定通过，最终采用 `0.30`，因为它在飞机低飞时更不容易把地面点纳入切片。

值得记录的是：任务一的三次成功其实带有运气成分——飞机的悬停高度恰好落在某一圈扫描线的 10 厘米窗口内。这说明默认值 `0.10` 在当前的雷达配置下只是「临界可用」，不是稳健可用。

但这个参数也不能一味放大。取值需要同时满足两个条件：覆盖 Livox 的多圈扫描线，以及留出足够的高度余量避开地面。`0.50` 虽然能通过，但飞机低飞时（约 0.5 m）切片下沿会碰到地面；`0.30` 在两者之间取了平衡，是实测可用的上限之一，不是理论最优值。

## 五、实验结果

### 5.1 测试方法

每次测试都完整重启仿真和节点。这一点是必须的，因为 `avoid_side` 是函数内 `static` 变量，只在进程启动时初始化，如果只重启节点而不重启仿真，或者复用进程，第二次的方向会沿用上次的锁定值，测试无效。

在锁定时刻加了一行日志：

```cpp
ROS_WARN("[LOCK] side=%d first_ry=%.4f F_c=%.3f rho=%.3f",
         avoid_side, ry, F_c, distance_c);
```

它挂在 `avoid_side == 0 → 非 0` 的跳变点上，全程只打一次。

### 5.2 三轮结果

- **第一次**：`side=1`，`first_ry=0.0004`，`F_c=0.002`，`rho=1.595`，**向左绕**，到达 `(6,0)`
- **第二次**：`side=-1`，`first_ry=-0.0020`，`F_c=0.012`，`rho=1.574`，**向右绕**，到达 `(6,0)`
- **第三次**：`side=-1`，`first_ry=-0.0019`，`F_c=0.012`，`rho=1.573`，**向右绕**，到达 `(6,0)`

三次全部到达目标，方向两次向右、一次向左。

### 5.3 数据解读

三个现象值得注意。

**第一，锁定位置极其稳定。** 三次 `rho` 分别是 1.595、1.574、1.573，全部紧贴 `R_outside = 1.6`，差异不到 2 厘米。说明每次都是在刚进入感知范围的第一帧就完成了锁定，触发条件一致。

**第二，锁定那一刻斥力几乎为零。** `F_c` 只有 0.002 到 0.012。因为 `rho` 刚过 1.6，`p_R × (1.6 - rho)` 的括号里只有 0.005 到 0.027。

这形成了一个有用的结构：**方向定得早，但那时还不产生位移；等斥力真正长起来时，方向已经不可能再变**。如果反过来，等斥力很大时才判断方向，一次误判就会直接撞上去。

**第三，决定方向的残差极小。** `first_ry` 的绝对值是 0.0004 和 0.0020，与同一时刻的 `F_c` 处于同一量级甚至更小。这说明锁定判据本质上是在给一个接近零的量取符号。

### 5.4 任务二（collision_2.world）

`collision_2.world` 里只有一根柱子，位置是 `(3.048, 0.022)`，半径 0.5、高 2。也就是说它几乎正好压在起点到目标的连线上，横向只偏了 2.2 厘米。

这个场景比任务一更极端，因为没有任何第二个障碍物可以提供不对称性，横向分量在理论上严格为零。

**第一次尝试（`z_band = 0.10`）**：失败。飞机完全没有避障动作，直接撞柱。日志中 `vel_collision` 全为 0，判定为感知没触发，具体原因见 4.1。

**第二次尝试（`z_band = 0.50`）**：成功，向左绕行，到达 `(6,0)` 并降落。随后把 `z_band` 收窄到 `0.30` 复测，同样稳定通过，最终采用 `0.30`。

以下数据取自 `z_band = 0.50` 的那一次运行：

- 锁定记录：`side=1`，`first_ry=0.0001`，`F_c=0.004`，`rho=1.592`
- 绕行方向：**向左**
- 结果：到达 `(6,0)` 并降落
- 避障介入比例：737 帧日志中有 450 帧的 `vel_collision_x` 非零，占 61%

`first_ry = 0.0001` 是三次实验里最小的值，比双柱场景的 0.0004 还要小一个量级。这完全符合预期：单柱正对时净横向分量趋近于零，只剩量化噪声。

值得注意的是，`first_ry` 这么小，如果只靠原始斥力分量，横向推力等于没有，飞机会被引力牢牢按在中线上。真正让它绕开的是迟滞里的强制下限——因为 `fabs(ry) < 0.4f * F_c` 必然成立，`ry` 被强行抬到 `0.4f * F_c`。随着飞机靠近，`F_c` 从 0.004 增长到限幅值，横向分量同步放大到 0.12，飞机才被一点点推开。

也就是说，任务二能够通过，**完全依赖 2.5 节那个强制偏置，原始的人工势场力在正对场景下是失效的**。

## 六、局部最优问题分析

### 6.1 现象

不加迟滞时，飞机飞到柱子前约 1.5 m 处开始左右摆动，摆幅越来越小，位置基本不动，但跟踪速度仍在向前推它，最终撞在柱子上。

### 6.2 根本原因

场景关于 `y = 0` 严格对称：两根柱子、起点、目标都在对称轴上。当飞机位于 `y = 0` 时，对两根柱子的距离完全相等，两个斥力大小相等、方向关于 `x` 轴对称，横向分量严格抵消。

数学上净横向分量为零，所以飞机应该直冲。但实际点云有量化误差，两根柱子的估计距离不会完全相等，横向分量剩下一个极小的净残差 `ry`。

这个残差的符号取决于哪一侧的点云多占了一个栅格，与飞机的位置、目标、甚至飞行意图都无关。于是 `angle_c` 在两根柱子之间反复跳动，`ry` 每帧翻号，横向推力平均为零。

这就是典型的**局部最优**：引力一直指向目标（正前方是柱子），斥力把飞机往后推，两力在柱子前沿达到平衡，飞机卡在势场的鞍点上，靠自己的力量出不来。

### 6.3 为什么调参数解决不了

几个直觉上的调法都无效：

- 减小 `voxel_leaf_size`：残差会变小，但在零附近抖动得更频繁，反而更难脱离
- 增大 `p_r`：两根柱子的斥力同时变大，抵消关系不变，净分量仍然接近零
- 减小 `R_outside`：锁定更晚，接近柱子时才判断，反应空间更小
- 增大 `p_xy`：只加强向前的推力，会让飞机更快撞上去

问题不在于参数大小，而在于**系统缺少打破对称的机制**。

### 6.4 解决方法

引入状态记忆：第一次进入避障区域时，用当时的残差符号锁定一个方向，之后不再更改，并用一个下限强制保证横向分量不低于 `0.4 F_c`。

这是把一个「每帧重新决策」的无状态系统，改成「决策一次、执行到底」的有状态系统。代价是丧失了应对障碍物突然换边的灵活性，收益是彻底消除了震荡。

### 6.5 验证

见第五节三轮数据。三次方向随机（右、右、左），但三次全部通过。

这说明当前方案保证的是「能否通过」，不保证「往哪边通过」。方向的随机性来自首帧量化残差，是这套方法在对称场景下的固有特性，不是缺陷。

## 七、参数说明

`avoidance.yaml` 中的参数及其作用：

- `target_x / target_y`：目标位置，本关为 `(6.0, 0.0)`
- `R_outside`：斥力作用的外边界，1.6 m
- `R_inside`：内外圈分界，0.9 m
- `p_xy`：跟踪速度比例增益，0.7
- `vel_track_max`：跟踪速度上限，0.30 m/s
- `p_R`：外圈斜率，0.45
- `p_r`：内圈斜率，1.5
- `vel_collision_max`：避障速度上限，0.30 m/s
- `vel_sp_max`：合速度上限，0.30 m/s
- `range_min / range_max`：使用的 bin 范围，0 到 359，即全向 360 度
- `z_band`：高度切片的容差。默认 0.10 m，但实测过窄会把 Livox 的稀疏扫描线整根滤掉，任务二中需放宽到 0.30 m 才稳定生效，具体分析见 4.1
- `min_obstacle_range`：点云近处裁剪，0.15 m，用于滤掉机体自身反射
- `max_obstacle_range`：点云远处裁剪，8.0 m

其中 `p_R`、`p_r` 的选择依据：内圈斜率是外圈的 3.3 倍，保证进入危险距离后斥力迅速增大；而外圈斜率较小，让飞机在接近阶段有平缓的过渡，不会突然大幅横移。
